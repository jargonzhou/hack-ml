Metamorphic Multi-Agent Systems represent an advanced paradigm in artificial intelligence where multi-agent systems (MAS) dynamically adapt their structure, behavior, or testing relationships to handle complex, evolving environments. In AI engineering, this term primarily manifests in two revolutionary contexts: **self-evolving multi-agent architectures** (like MetaAgent or MetaGPT) that structurally morph to solve tasks, and **automated metamorphic testing workflows** (such as ARMeta or AutoMT) where agents generate relational logic to validate AI behavior. [1, 2, 3, 4, 5] 
------------------------------
## Core Paradigms of Metamorphic Multi-Agent Systems## 1. Self-Evolving and Structural Metamorphism
In this paradigm, the system changes its own structural configuration based on the task description. Instead of maintaining static agent definitions, the system alters its behaviors and interactions dynamically. [6, 7, 8] 

* Finite State Machine Orchestration: Frameworks like the MetaAgent Framework model agent behaviors as states within a Finite State Machine (FSM). The entire system structure can transition, expand, or run a "State Traceback" to rewrite its own pipeline when errors occur. [9, 10] 
* Role Metamorphism: Individual large language model (LLM) agents morph their identities (e.g., from Product Manager to Code Developer) depending on standard operating procedures. [11, 12, 13] 
* Decentralized Evolution: Advanced architectures use evolutionary algorithms to let agent populations self-organize, adapt their communication graphs, and optimize their collaboration overhead without human intervention. [14, 15, 16] 

## 2. Agentic Metamorphic Testing (MT)
Testing complex AI networks suffers from the "oracle problem"—it is difficult to know the uniquely correct output for a given prompt. Metamorphic agent systems resolve this by orchestrating teams of agents to extract Metamorphic Relations (MRs) that must remain true across varying inputs. [1, 4, 17, 18, 19] 

- [System Inputs] ──> [Requirement Extraction Agent] ──> [MR Generation Agent] ──> [Execution & Verification Tool]


* Requirement Extraction Agents: These parse functional specs or local traffic laws to map system constraints. [20, 21] 
* MR Generation Agents: Using "Given-When-Then" syntaxes, these agents formalize logic transformations. For instance, changing user demographics shouldn't alter a classification agent's fairness. [1, 4, 22] 
* Refiner and Critic Agents: High-tier models act as critics to eliminate cascading hallucinations and code instabilities within the testing loop. [12, 22]

## Primary Applications

* Robotics & Pathfinding: In Multi-Agent Path Finding (MAPF), metamorphic relationships ensure that if path obstacles shift slightly, agent paths morph optimally without causing gridlocks or collisions. [25, 26] 
* Autonomous Vehicles: Systems use multi-agent frameworks to read traffic guidelines, visually analyze road environments, and generate downstream physical simulations to test safety limits. [20] 
* Enterprise Software Generation: Simulating entire operational pipelines where digital workflows reshape themselves around the constraints of a project description. [12, 27]
